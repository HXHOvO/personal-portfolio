1

把 Claude Code 接入飞书机器人

场景：我日常用 stepcode 调 Claude Code，但团队其他人不用 stepcode。 想让同事在飞书里@机器人就能用 Claude——通过 lark-channel-bridge 这条官方路径。

问题：官方路径走不通——这台机器用的是 stepcode 中转鉴权，不是官方登录。 三个具体的根因：

  • secrets-getter "world-writable" 审计错（Windows）： Node/Go 在 Windows 不读 NTFS ACL，可写文件一律报 0666；Go 读 wrapper 时 mode 0o444 → 审计失败。
  • 裸 claude 没鉴权：bridge spawn 的子进程拿不到 stepcode 注入的 ANTHROPIC_*，立刻 Not logged in 退出。
  • prompt 元字符被 cmd 二次解析：bridge 把 prompt 作为 -p <prompt> 经 cross-spawn → cmd /c → claude.exe 解析， prompt 里的 >/|/& 被当成重定向/管道，输出导走，飞书显示 (no content)。

补丁核心：直接 spawn claude.exe + 注入 stepcode 鉴权

不让 bridge 经 cmd shell 调 claude，改用 claude.exe 全路径（CreateProcess 直传 argv，完全不过 cmd）。 同时 spawn 时从 ~/.stepcode/config.json 注入 ANTHROPIC_AUTH_TOKEN 等环境变量。 

// 改 bridge 源码 ClaudeAdapter 里的 spawn 部分
const __stepEnv = (() => {
  try {
    const home = process.env.USERPROFILE || process.env.HOME || "";
    const cfg = JSON.parse(readFileSync(home + "/.stepcode/config.json", "utf8"));
    const e = {};
    if (cfg.apiKey) e.ANTHROPIC_AUTH_TOKEN = cfg.apiKey;
    if (cfg.baseUrl) { e.ANTHROPIC_BASE_URL = cfg.baseUrl; e.ANTHROPIC_API_URL = cfg.baseUrl; }
    const cm = (cfg.agentModels && cfg.agentModels.claude) || {};
    if (cm.model) e.ANTHROPIC_MODEL = cm.model;
    if (cm.smallModel) { e.ANTHROPIC_DEFAULT_HAIKU_MODEL = cm.smallModel; e.ANTHROPIC_SMALL_FAST_MODEL = cm.smallModel; }
    return e;
  } catch { return {}; }
})();
const child = spawnProcess(this.binary, args, {
  cwd: opts.cwd,
  env: mergeProcessEnv(process.env, { ...buildLarkChannelEnv(this.larkChannel), ...__stepEnv }),
  stdio: ["ignore", "pipe", "pipe"]
});

关键学习

表面上是"调通一个飞书机器人"，实际上练的是在 Windows 特定环境下做根因分析 + 最小化补丁的能力。 三个根因都不在 Claude 本身，而在"工具链的边界条件"——这是非 Mac 工程师最容易踩的坑。

踩坑提醒：补丁改的是 node_modules 里的文件，bridge 升级后会失效。要做"重装后重打补丁"的流程提醒。

会议纪要 skill：飞书录音 → 结构化纪要

场景：HR 面试、跨团队技术讨论、产品评审会之后，整理纪要又累又容易漏关键信息。 想法：把飞书录音转写文本丢给 Claude，自动生成结构化纪要 + 飞书卡牌。

产品设计：硬规则 + 分场景模板

这个 skill 之所以能稳定用，关键不是 prompt 多巧，而是 5 条硬规则：

  • 只写文档明确出现的信息——人名/公司/数字/流程/时间点，必须有转录原文支撑
  • 禁止脑补——面试官名字、对标公司、候选人意图排序、未陈述的结论一律不写
  • 文档隔离——每个候选人/会议独立处理，不和上一个跨文档 carry over
  • 信息不足时宁缺毋滥——缺字段就写"未明确提及"
  • 直接按 skill 内置规范发飞书卡牌——用 msg_type=interactive

关键学习

会议纪要 / 面试纪要这类 AI 工具，"准确性"比"丰富性"重要 100 倍。
宁可字段空着，也不要脑补一个看起来合理但实际没说的结论——这是 HR 场景对 AI 的核心约束。

为什么这两个放在一起

飞书 Claude 集成展示的是"在复杂环境（Windows + 工具链边界）下做根因分析"的能力； 会议纪要展示的是"把 AI 用在高频重复工作上"的能力。

两者合起来想说明一件事：我能在不同约束下把 AI 工具搭出来—— 不管是 hack 工具链，还是设计严谨的 skill 模板。
